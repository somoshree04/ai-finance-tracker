
# 🧠 ML Architecture  

The analytical intelligence layer of the application. It transforms raw, wide-format personal finance data into processable transactional records and evaluates incoming transactions in real time to flag anomalous spending patterns.

---

## 📊 Dataset Source

The predictive engine is trained on the **Indian Personal Finance and Spending Habits** dataset from Kaggle, stored locally at:

```
../data/data.csv
```

### Original Structure (Wide Format)

Each row represents a single user, with spending spread across parallel columns:

- **Demographics / Base Info:** Income, Age, Occupation, etc.
- **Spending Dimensions (11 columns):** Rent, Loan_Repayment, Insurance, Groceries, Transport, Eating_Out, Entertainment, Utilities, Healthcare, Education, Miscellaneous

---

## 🔄 Architecture & Data Workflow

The pipeline bridges the gap between static row-per-user spending tables and real-time, transaction-based anomaly scoring.

```
[ Kaggle data.csv ]
        │
        ▼  (wide-to-long restructuring)
  data_conv.py ───> melted_df [['amount', 'category_id']]
        │
        ▼  (trained on processed historical baseline)
[ anomaly_model.pkl ] (Isolation Forest)
        │
        ▼  (real-time transactional scoring)
   model.py    ───> predict_anomaly(amount, category_id) ───> True / False
```

---

## 📄 File Breakdown

### 🛠️ `data_conv.py` — Pipeline Transformer

Dynamically targets `data.csv`, isolates the 11 spending categories, and restructures the matrix into an unpivoted long-format layout suited for transaction parsing.

**Step-by-step:**

1. **Dynamic Pathing** — Uses `os.path.dirname(os.path.dirname(__file__))` to resolve the project root and locate `/data` without hardcoded paths.
2. **Data Melting** — Applies `pd.melt()` to compress the 11 spending columns into two fields per record: `category` (spending type) and `amount` (cash value).
3. **Categorical Encoding** — Converts category strings to numeric IDs via `.astype('category').cat.codes` (e.g., `0` → Eating_Out, `1` → Education).
4. **Output** — Returns a clean dataframe with just `amount` and `category_id`, along with a dictionary to map IDs back to human-readable labels.

---

### 🔮 `model.py` — Real-Time Inference Engine

The operational endpoint. When a user submits a transaction on the frontend dashboard, this script ingests the parameters and uses a pre-compiled model to determine whether the spend is normal or anomalous.

**Step-by-step:**

1. **Model Loading** — Checks for `anomaly_model.pkl`, an Isolation Forest model trained on the baseline generated by `data_conv.py`.
2. **Feature Alignment** — Wraps runtime parameters (`amount`, `category_id`) in a single-row pandas DataFrame, maintaining the exact column schema the model expects.
3. **Isolation Forest Prediction** — Calls `model.predict()`:
   - A transaction in a sparse data region (extreme amount for its category) scores as `-1`.
   - Returns `True` (anomaly detected) if `prediction[0] == -1`, otherwise `False` (normal).

---

## ⚙️ ML Features

| Feature | Type | Description |
|---|---|---|
| `amount` | Float | Monetary value of the transaction |
| `category_id` | Integer | Encoded spending category (0–10) |
